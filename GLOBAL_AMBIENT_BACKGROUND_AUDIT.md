# Global ambient background audit

Implemented October 4, 2026.

## Integration

- `components/GlobalAmbientBackground.tsx` owns the text-free artwork and deterministic route selection.
- `app/ambient-background.css` owns the palette variations, motion, layering, responsive density, and reduced-motion rules.
- `app/layout.tsx` mounts one viewport-sized background outside the existing providers and page content. All public, auth, account, and admin layouts inherit it.
- `app/global-error.tsx` reuses the artwork directly when the root layout is unavailable.
- Only page canvas backgrounds become transparent. Cards, inputs, product images, menus, dialogs, loading overlays, and admin tables retain their existing surfaces.

## Variants

| Variant | Routes | Treatment |
| --- | --- | --- |
| Champagne | Homepage, products, nested product routes, other public routes | Warm gold/amber silk, rose light, curved lines |
| Blush | Promotions, about, contact and their nested routes | More blush/plum haze and diagonal silk |
| Pearl | Auth, account, orders, cart, checkout, confirmation and policies | Softer cream/gold and quieter curves |
| Admin | `/admin` and every nested route, including login | 18% desktop / 13% mobile strength, smaller motion, longer loops, fewer accents |

Unknown public routes inherit Champagne. No random values, catalog text, scent vocabulary, or brand labels are generated by the background. The existing homepage hero source and its floating words, entrance, fade, and richer artwork remain unchanged; its original cream canvas is preserved explicitly.

## Browser coverage

Passed 71 route/motion views with no browser JavaScript errors:

- Production public routes at 390px and 1440px: homepage, products, promotions, about, contact, login, register, verify email, forgot password, reset password, auth action, all four policy pages, admin login, and 404.
- Isolated real UI with sample records at 390px and 1440px: homepage, products, promotions, account, account security, orders, checkout, admin dashboard, products, orders, promotions, customers, brands, announcements, messages, testimonials, and settings.
- Opened product details, shopping bag, and the admin product editor at both widths; checked readable surfaces and working click/focus/dismiss behavior.
- Opened order confirmation at both widths with an entirely in-memory checkout response and sample upload. No live orders, uploads, emails, or database writes occurred.
- Additional product layout overflow checks at 320px, 768px, 1024px, and 1920px.

This application currently implements product details, cart, and order confirmation as overlays rather than separate routes. Their existing behavior was preserved.

Live Firebase reads encountered network restrictions in this environment. Protected UI and populated tables were inspected using isolated sample records; this audit does not claim live authenticated-data verification.

## Final requirements

1. One shared ambient layer is inherited by all normal page routes.
2. Floating hero vocabulary stays inside the existing hero; the global artwork has no text nodes.
3. No decorative hero vocabulary appeared on other tested routes.
4. Every decorative layer uses `pointer-events: none`; browser hit tests never selected the background.
5. No horizontal document overflow appeared in the tested views.
6. Native wheel scrolling worked immediately, and the background stayed fixed to the viewport during scrolling.
7. Forms, cards, images, dialogs, and data surfaces remained readable in visual inspection.
8. Admin uses visibly restrained opacity, density, and motion.
9. Mobile keeps the same visual identity while hiding the secondary ribbon, second glass strip, and second accent.
10. Reduced motion stops all ambient animations, including when the preference changes while the page is open.

Hidden-tab animation pause/resume and dark mobile palette strength also passed. Hero artwork was visually compared with its original cream canvas.

## Performance

The background has one SVG with five simple paths, two gradient fields, two glass accents, and two small drifting accents. At most eight decorative elements animate on desktop, six on mobile, and five in admin. Animation uses only predefined CSS transforms and opacity with varied durations and negative delays. There are no blur filters, canvas/WebGL effects, scroll listeners, wheel interception, mouse tracking, per-frame JavaScript, or per-frame React updates in the new system. The only effect pauses animation when the document becomes hidden.

Scroll behavior was tested in the browser; no device-specific frame-rate benchmark is claimed.
